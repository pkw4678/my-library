# My Library v3.1 — 승인제 회원가입 클라우드 버전

기존 My Library v3.0 UI를 유지하면서 **회원가입 → 이메일 확인 → 관리자 승인 → 개인별 라이브러리** 흐름을 연결한 정적 웹앱이다.

## 파일

- `index.html`: 일반 사용자 페이지 및 기존 My Library 기능
- `admin.html`: 별도 관리자 페이지 (승인·거절·정지·재승인)
- `cloud.js`: Firebase Auth, Firestore 데이터 동기화, 사용자 세션
- `admin.js`: 관리자 인증 및 회원 관리
- `firebase-config.js`: Firebase 클라이언트 설정 (직접 입력 필요)
- `firestore.rules`: Firebase Firestore 보안 규칙 (반드시 배포 필요)
- `DEPLOY_KO.md`: 설정 및 배포 절차
- `TEST_PLAN.md`: 실제 서비스 연결 후 검증 시나리오

**중요**: Firebase 설정값이 들어 있지 않은 상태에서는 로그인·저장 기능이 동작하지 않는다. Firebase 프로젝트는 사용자가 생성해야 하며, 이 패키지로 자동 배포된 상태는 아니다.

실행은 HTTP(S)에서 한다. `file://` 방식으로 더블클릭하지 말고 GitHub Pages 또는 로컬 웹서버를 사용한다.

## 저장 구조

- `users/{uid}`: 신청 프로필, 역할, 승인 상태
- `users/{uid}/items/{itemId}`: 작품별 기록
- `users/{uid}/collections/{collectionId}`: 컬렉션
- `users/{uid}/trash/{itemId}`: 휴지통
- 브라우저의 `my-library-account-{uid}-*`: 작성 초안·복구 지점·개인 환경설정 (브라우저 한정)

기존 v3.0 브라우저 저장소는 자동 이전하지 않는다. **구버전 JSON 백업을 새 계정에서 명시적으로 가져오기**로 이관한다.

## 알려진 제한

- 이미지를 Firebase Storage에 업로드하지 않는다. 외부 이미지 제공처의 링크가 차단되면 표지가 실패할 수 있다.
- 복구 지점(스냅샷)은 현재 브라우저에만 보관한다. 작품/컬렉션/휴지통은 Firestore에 보관된다.
- 실시간 다른 기기 변경을 즉시 동기화하기 위해 화면을 새로고침하면 서버 상태가 조회된다. **동시 수정의 모든 충돌을 자동 병합하는 기능은 없다.** 동일 작품을 두 기기에서 동시에 수정하면 최신 서버 저장 상태가 우선하며, 필요한 경우 JSON 백업으로 복구한다.
- 네트워크 중단 시 제출한 변경의 서버 저장이 보장되지는 않는다. 작품 편집 초안은 해당 계정의 브라우저에 남는다.
- Firestore Spark 무료 한도 내에서 월 이용료 0원을 목표로 한다. 무제한 또는 영구 무료를 보장하지 않는다.
- 이메일/비밀번호 회원가입 방식이며 본 서비스 자체에서 알림 메일을 관리자에게 전송하지 않는다. 관리자는 `admin.html`에서 신청 목록을 확인한다.
